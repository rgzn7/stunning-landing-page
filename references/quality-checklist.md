# 交付前自检清单

逐项检查。有浏览器工具时，实际打开页面截图验证首屏和滚动后的状态，不要只靠读代码想象。

## 一、惊艳度检查（最重要）

- [ ] **首屏 0.5 秒测试**：页面打开瞬间有视觉冲击吗？（巨字、渐变流动、进场动画至少占一样）
- [ ] **有明确的签名时刻**：全页有一个值得截图的高光效果，而不是十个平庸的 fade-in
- [ ] **滚动或状态切换有节奏**：紧凑段落与大留白段落交替；若是单屏 HUD 舞台，Home / Work / Contact 状态变化要清楚
- [ ] **缓动统一**：全页使用同一套 ease 和时长体系，没有"PPT 切换感"的 linear 动画
- [ ] **动画与内容呼应**：每个动画都在强化它所在区块的卖点，而不是为了动而动
- [ ] **hover 有生命**：所有可点元素（按钮、卡片、链接）都有 hover 反馈

## 二、质感修复表（"动了但不惊艳"时对症下药）

| 症状 | 病因 | 处方 |
|------|------|------|
| 像 PPT 切换 | 缓动太线性/时长太短 | 换 `power3.out`，时长加到 0.8s+，进场加 `y: 60` 位移 |
| 元素同时蹦出来 | 没有 stagger | 组内元素加 0.08~0.15s 错峰 |
| 页面发"飘"没有重心 | 什么都在动 | 砍掉一半动画，每屏只留一个主角 |
| 看起来廉价/塑料感 | 纯色平涂 + 默认阴影 | 加噪点 overlay、调整投影为大而柔、色彩加渐变层次 |
| 滚动生硬 | 没有平滑滚动 | 上 Lenis；scrub 动画加 0.6~1 缓冲 |
| 标题没气势 | 字号太保守 | Hero 标题上 `clamp(3rem, 8vw, 7rem)`，加紧字距 |
| 暗色页面发灰发闷 | 纯黑底+纯灰字 | 底色改 `#0a0a0c` 微调色相，关键元素加品牌色辉光 |
| 配色土 | 饱和度/明度失衡 | 回 theme-to-style.md 对照基调原型的配色规则重调 |
| HUD 像调试信息 | 状态文本太多、层级抢主视觉 | 只保留品牌、导航、坐标/时间/状态；HUD 字号降到正文的 45%~65% |
| 3D 主视觉空或糊 | canvas 未渲染、相机距离错误、材质太透明 | 用浏览器截图验证 canvas 非空；加静态 SVG/文字 fallback；调相机和灯光 |
| 作品区被 3D 干扰 | 缺少不透明遮挡层，内容直接压在 3D 上 | 给 Work/Archive 区加 opaque 档案面板或 2D texture canvas，明确盖住底层 3D |

## 三、技术检查

- [ ] 浏览器 console 无报错（CDN 加载失败、null 引用是高发区）
- [ ] 所有图片可显示：占位图用渐变/SVG/picsum，无破图
- [ ] **全页零 emoji**：图标一律来自在线图标库（Remix Icon / Iconify）或内联 SVG，emoji 渲染因系统而异且显廉价
- [ ] 动画只用 transform/opacity，滚动时无明显掉帧
- [ ] WebGL/Three.js 场景已截图验证非空，且 `prefers-reduced-motion` 下有静态 fallback
- [ ] OS-HUD 的 Work/Archive 区有不透明遮挡舞台层，滚过封面后 3D 不影响作品阅读
- [ ] `prefers-reduced-motion` 降级已实现
- [ ] JS 失败时页面内容仍然可读（渐进增强，初始隐藏不要写死在 CSS）
- [ ] 文件头部注释含 @Date / @Author / @Discription，代码注释为中文

## 四、响应式检查

- [ ] 375px 宽度下：标题不溢出、布局不横向滚动、字号用了 clamp
- [ ] 鼠标类交互（视差/磁性/光标/3D 倾斜）在触屏下已禁用且不留空白
- [ ] 横向滚动章节在窄屏有替代方案（纵向排列或原生横滑）
- [ ] pin/sticky 段落在移动端高度正常，无内容被截断
- [ ] OS-HUD 页面在移动端改为纵向舞台，固定状态栏不遮挡标题、作品图和联系信息
- [ ] 贴纸/印章/漂浮装饰在 375px 宽度下不会压住主标题或 CTA

## 五、内容检查

- [ ] 文案是为主题量身写的，有真实感（具体数字、具体场景），不是 "Lorem ipsum" 或万能套话
- [ ] 信息架构完整：常规落地页需要导航、Hero、3~5 个卖点区、社会证明（数据/证言/logo 墙）、CTA、页脚；作品集/OS-HUD 页至少需要身份声明、作品档案、能力说明、联系方式
- [ ] CTA 在 Hero 和页尾至少各出现一次；作品集可用 `Work` / `Contact` / 邮箱 / 社媒链接承担行动入口

## 六、交付说明

向用户交付时说明：

1. 页面的叙事结构（每个 section 讲什么）
2. 签名动画是什么、灵感来自哪个网站的什么模式
3. 占位图片/文案在哪里、如何替换
4. 如果使用 OS-HUD 分支，说明 Home / Work / Contact 状态如何切换，以及 HUD 里的时间、坐标、主题等状态如何改
5. 如需移植到 Vue/React 项目，动画初始化代码应放在何处（mounted/useEffect + 组件卸载时 `ScrollTrigger.kill()`）
